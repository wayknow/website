EditThisCookie Alternatives: What to Use After It Was Removed (2026)

Published August 13, 2026 · 6 min read

If you're here, you already know: EditThisCookie is gone. It was removed from the Chrome Web Store in late 2024 — the victim of Chrome's Manifest V3 migration — and millions of developers lost their daily cookie editor overnight.

But here's the part that should worry you more: a malicious clone took its name. An extension called "EditThisCookie®" appeared on the store, was downloaded by tens of thousands of users, and was confirmed by security researchers to be malware — it injected ads, attempted phishing, and could steal sensitive data. It's since been removed, but the search for the old tool is exactly where people get burned.

So: what do you use now? I've tested every real option. Full disclosure — I built one of them (CrumbKit), and I'll be explicit about where it wins and loses.

Why EditThisCookie stopped working

Chrome retired the Manifest V2 (MV2) extension platform in favor of MV3. EditThisCookie never migrated — its background scripts and extension model were incompatible with MV3's service workers — so it stopped receiving updates, and for many users stopped loading entirely. The removal from the store was the final step.

The lesson from that transition: an old, unmaintained cookie editor is a liability, and cookie managers are a target for clones because cookies are exactly what session hijackers want. Whatever you install now should be MV3-native, actively maintained, and ideally open source.

1. Chrome DevTools — the zero-install baseline

Right-click → Inspect → Application tab → Cookies. Double-click any field to edit it. No install, no risk, always works.

The limits: no search across domains, no filtering, no export/import, and no way to see which cookie was just set by the server. Fine for the occasional fix; painful if you edit cookies daily.

2. CookieMate — the open-source drop-in

An MV3-native, MIT-licensed replacement with the feature that matters most for you specifically: it imports EditThisCookie's JSON backups directly. If you still have an old export from EditThisCookie, this is the smoothest migration path. View, edit, add, bulk-delete, and wipe cookies, with light/dark themes and no telemetry.

The catch: it's a straightforward editor — no scheduled cleanup, no server-side interceptor, no privacy scoring.

3. CookieJar — the feature-rich contender

A modern MV3 cookie manager built as a direct EditThisCookie replacement: auto-classifies cookies into categories, scores each site's privacy, manages profiles (dev vs. prod cookie sets), exports in multiple formats, and handles CHIPS partitioned cookies. It has a free tier with a paid Pro tier.

Honestly a solid tool — the closest thing to "EditThisCookie with a 2026 paint job." The paid tier is where it differs from the free options below.

4. CrumbKit — the fully free power tool

I built CrumbKit after the removal, and it's my honest take on what a cookie editor should be in 2026: everything free, open source (MIT), zero network requests, MV3-native.

Where it genuinely beats the field:

  • Set-Cookie interceptor — watch every Set-Cookie header a server sends and add it to your session with one click. No other editor in this list shows you which cookie was just set and by which response.
  • Scheduled auto-cleanup — purge tracking cookies by domain, category, or age, hourly or daily.
  • 6 export formats — JSON, Netscape (curl/wget), cURL command, CSV, Puppeteer script, and Set-Cookie headers. If you script against cookies, this is the differentiator.
  • Batch edit, profiles, privacy score, undo (50 steps), whitelist protection, CHIPS partitioned-cookie support, and real-time cookie search.

Where it loses: it's younger than the alternatives (I'm a solo maintainer), and if you only need to change a cookie value once a week, DevTools is genuinely enough.

Migrating from EditThisCookie

If you still have an old backup: CookieMate imports EditThisCookie's JSON format directly, and CrumbKit imports JSON and Netscape formats — either way your domains, paths, and flags survive the move. If you don't have a backup, re-login to your sites; there's no way to resurrect cookies Chrome already discarded.

Which one should you use?

  • You edit a cookie once a month → DevTools, nothing to install
  • You want your old backup to just work → CookieMate
  • You want maximum features and a free tool → CrumbKit
  • You're fine paying for a maintained Pro tool → CookieJar
  • You debug sessions professionally → CrumbKit, for the Set-Cookie interceptor alone

Security checklist before you install anything

  • Check the store name carefully. The malware clone used "EditThisCookie®" — a legitimate editor won't brand itself with the name of the dead original.
  • Prefer open source. A cookie editor has access to your sessions on every site; you should be able to audit what it does. (CrumbKit and CookieMate are both MIT.)
  • Watch the permissions. A cookie editor legitimately needs cookies — anything asking for it and broad host permissions without a reason is a red flag.
  • Check maintenance recency. The MV2 graveyard is full of tools that were great in 2021 and abandoned since.

FAQ

Is EditThisCookie still available anywhere? The original is gone from the Chrome Web Store. Old copies float around third-party sites — don't install those; that's exactly how the malware spread.

Can I edit cookies without an extension? Yes — DevTools' Application tab can edit any cookie, just less efficiently.

What are CHIPS partitioned cookies? Chrome's privacy feature that separates third-party cookies per top-level site. A modern cookie editor needs to handle them — both CookieJar and CrumbKit do.

Why do cookie editors need so many permissions? Editing cookies is the core — it's inherently powerful. That's why open source and zero-telemetry matter here more than in any other extension category.
